# chrome-profile-check

**Узнайте, что на самом деле находится внутри ваших профилей Chrome — и что будет потеряно при обычном копировании — до того, как вы что-либо скопируете.**

Копирование папки профиля на другой компьютер выглядит так, будто оно работает. Размер совпадает, все файлы на месте. Затем вы открываете его, и вы вышли из всех аккаунтов, паролей нет, и ничто не объясняет почему.

Этот скрипт заранее объясняет причину. Это диагностика, а не инструмент для переноса.

```
pip install chrome-profile-check
chrome-profile-check
```

Python 3.7+, только стандартная библиотека, без зависимостей. Пути Windows, macOS и Linux определяются автоматически; интерес представляет именно сбой в Windows.

## Что он вам сообщает

```
========================================================================

  Work   (Default)
    size          3.3 GB total, of which 2.1 GB is cache you never need to move
    worth moving  1.1 GB
    cookies       412
    saved logins  69
    bookmarks     229
    extensions    30
      v20 (App-Bound, tied to this Windows account) 412 cookies

  Shop   (Profile 2)
    size          379 MB total, of which 217 MB is cache you never need to move
    worth moving  162 MB
    cookies       22
    saved logins  1
    bookmarks     3
    extensions    4
      v20 (App-Bound, tied to this Windows account) 22 cookies

------------------------------------------------------------------------
WHAT A PLAIN FOLDER COPY LOSES
------------------------------------------------------------------------
  434 cookies use App-Bound encryption (v20). They are bound to this
  Windows account: copied to another machine - or to another account on
  this one - they decrypt to nothing, and every site asks you to log in
  again. This is Chrome's own protection, not a bug in your copy.
  ...
```

Из этого можно узнать четыре полезные вещи:

- **какую часть папки занимает кэш.** Обычно больше половины. Люди копируют гигабайты кэша по сети и удивляются, почему это занимает весь вечер;
- **сколько файлов cookie, сохраненных логинов, закладок и расширений** на самом деле содержит каждый профиль — это полезно, когда вы решаете, какие профили стоит сохранить;
- **какой ключ защищает файлы cookie.** `v10`/`v11` означает старый ключ машины; `v20` означает шифрование App-Bound, появившееся в Chrome 127, которое привязывает значение к одной учетной записи Windows;
- **что переживет копирование, а что нет**, о чем прямо сказано в конце.

## Чего утилита никогда не делает

Это важнее списка функций, потому что файл, который она читает, — самый чувствительный на вашем диске:

- **она ничего не расшифровывает.** Ни файлы cookie, ни пароли, ни ключ;
- **она не печатает ни одного значения.** Только количество, размеры и трехбайтовый тег версии перед каждым файлом cookie — тег указывает, какая схема зашифровала остальное, и это не содержимое;
- **она ничего не пишет.** Базы данных открываются с `mode=ro&immutable=1`, поэтому sqlite не устанавливает блокировки, и работающий Chrome не прерывается. Худший вариант — это немного устаревшие данные подсчета;
- **она никуда ничего не отправляет.** В файле вообще нет сетевого кода — прочтите его, в нем менее 300 строк.

Если профиль активно используется, некоторые счетчики возвращают `unreadable (Chrome running?)`. Это честный ответ, а не проблема, которую нужно обойти.

## Использование

```
chrome-profile-check                    # каждый найденный профиль Chrome
chrome-profile-check --json             # машиночитаемый формат
chrome-profile-check --dir "D:\Profiles"  # каталог User Data в другом месте
```

Или без установки: `python chrome_profile_check.py`.

## Краткая суть проблемы

Начиная с версии Chrome 127 в Windows, значения файлов cookie шифруются ключом, который сам защищен шифрованием App-Bound — он привязан к учетной записи Windows, в которой был создан. Скопируйте папку на другой компьютер или в другую учетную запись на том же компьютере, и файлы cookie не расшифруются. Сессии исчезнут; вам придется снова входить в систему везде.

Что действительно сохраняется: закладки, история, расширения, настройки, автозаполнение. Пароли хранятся под той же защитой, привязанной к учетной записи — собственный экспорт Chrome в CSV является поддерживаемым способом их переноса.

Поэтому честный итог: **копирование папки переносит ваши настройки, а не ваши сессии.** Любой, кто обещает иное, описывает старую версию Chrome или то, что вам не следует запускать на своей машине.

## Почему это существует

Мы разрабатываем [Morfiade](https://morfiade.com/en/), менеджер профилей Chrome для Windows, и этот вопрос возникает постоянно: *почему мой скопированный профиль все потерял?* Ответ остается неизменным, независимо от того, используете ли вы когда-либо нашу программу, поэтому этот ответ оформлен как отдельная, открытая утилита.
